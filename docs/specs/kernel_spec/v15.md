# Horizon: Substrate — Concurrent Streaming Dataflow Runtime

**Status:** DRAFT v15. Three changes against v14, on engineering
merit:

1. **`ProducerEvent` is flattened.** v14 wrapped every Producer-emitted
   event in a `ProducerEvent` control-plane kind. The kind namespace
   already distinguishes runtime events (`substrate.*`) from
   application events (user-declared kinds), so the wrapper added a
   layer for no semantic gain. An application event is now an envelope
   with a `producer` field; the act of being on the log after
   validation is what "post-validation" means. Reduces frame size,
   halves parse cost on the hot path.

2. **`RunStarted` is added as a lifecycle kind.** Frame 0 of every
   record. Carries the topology manifest: registered Producer kinds
   with schema descriptors, Trigger/Route/View/policy identifiers,
   cooldown flags, baseline metadata (fixtures, seeds, environment).
   Initial topology-declared Producers attribute causal provenance to
   it — without this, provenance closure has dangling roots.

3. **`InputBuildFailed` is added as a lifecycle kind.** v14 was silent
   on what happens when a Trigger's `input_builder` raises. Three
   options: silently not fire (a hidden decision, violates "all state
   on the log"), crash the run (over-reaction), or emit a typed event
   (the right answer). Now: a typed event recording trigger, firing
   key, and error.

Otherwise unchanged from v14: same eight primitives, same vocabulary
discipline, same non-goals, same composition story, same append cycle,
same load-bearing commitment. Spec-only design document.

## The load-bearing commitment

All state lives on the log. Sealed inputs (Producer contract) plus
Routes-at-instantiation-boundaries (Route contract) mean a Producer
cannot be steered mid-life and cannot checkpoint except by emitting.
Long-lived stateful computations — a simulator holding a world, a
model mid-generation — participate by externalising their state as
events and being re-instantiated. The population-simulation example
works precisely because world-state is a Producer emitting every
tick. This commitment buys replay, cross-instantiation safety, and
untrusted-Producer tolerance; it taxes long-lived internal state.
Every downstream decision in this document is checked against it.

## What this is

Substrate is an abstract orchestration runtime. You bring computations
— LLMs, ML models, deterministic transforms, subprocesses, simulators,
parsers, test runners, sensors, anything that takes typed input and
emits typed events — and the substrate runs them concurrently,
coordinates them through a shared event log, and creates new ones
dynamically when conditions on the log are satisfied.

The mainline LLM orchestration tools (Aider, Claude Code, Cursor,
Cline, AutoGen, CrewAI, MetaGPT) assume one strong model with a tight
synchronous tool loop, or chat-based turn-taking between named roles.
LangGraph generalises further with cycles and conditional edges over
mutable shared state, but executes one node at a time and declares its
graph statically. Substrate sits on a different axis: N concurrent
computations, an append-only event log instead of mutable state, and
dynamic creation of new computations as the log evolves.

The point is to express topologies that the existing tools can't:
code-writing teams with concurrent writers and live verification,
ensembles of weak models adjudicated by a stronger one, adversarial
pairs streaming at each other from t=0, recursive decomposition where
solvers spawn sub-solvers, simulations, conversations, anything where
multiple streaming computations need to coordinate without N²-wiring
between them.

## Why this is non-obvious

This is not a more complicated agent loop. It is a different execution
model: concurrent streamed computation with predicate-triggered
topology evolution.

The mainline LLM tools — Aider, Claude Code, Cursor, Cline — share one
shape: one strong model, a set of tools, a tight synchronous
request/response loop. The chat-multi-agent direction (AutoGen,
CrewAI, MetaGPT) is the same shape with a turn-taking scheduler and
prompt-defined "roles." Their primitives are *model call* and *tool
call* with synchronous semantics. There is no buffer to predicate
over, no overlap to exploit, no auxiliary producer running in parallel
and injecting mid-stream. This substrate is on a different axis from
theirs, not further along the same one.

## The bus

The bus is the runtime's coordination point. The v14 kernel separates
three things v13 conflated: an admission queue (bounded, the
backpressure mechanism), a log (append-only, hot tail in RAM + cold
spill), and Views (RAM-resident, incrementally maintained).

### Memory model

**Admission queue (bounded).** Producers do not append directly; they
submit emissions to a bounded admission queue. A single writer drains
the queue and runs append cycles. Backpressure is `await submit()`
blocking when the admission queue is full. Space opens because the
writer genuinely consumes the queue. The admission-queue bound is the
credit pool, sized at implementation time. Control-plane events
generated inside the writer (see step 6 below) bypass admission —
they are part of the current drain, cannot deadlock against it, and
cannot be starved by payload traffic.

**Log (append-only, grows monotonically for the run).** Hot tail of
recent events stays in RAM; sealed older segments spill to disk. This
is safe because the hot path never reads raw history: Predicates read
Views (incremental, in RAM), Routes stage at append time, and the
only consumers of deep history are pull-Routes, `input_builder`s
doing explicit historical queries, and replay — all of which may read
through spilled segments at non-hot-path cost.

**Views (RAM-resident, incrementally maintained).** Each subscribes
to a set of event kinds or producer ids, updated synchronously inside
the writer during the append cycle.

### The append cycle

Appends are processed by a single writer. For each admitted event,
the writer runs:

1. **Validate** the event against the emitting Producer kind's
   declared schema. An invalid emission is **not dropped from the
   record**: it is wrapped as a `ProducerEmittedInvalidEvent`
   control-plane event with the raw payload inside and a typed reason
   attached, and that wrapper is processed through the remaining
   steps like any event. It is sequence-numbered, on the log, visible
   to replay, and matchable by Predicates. Predicates on the
   Producer's declared payload kinds never see it; Predicates on
   `ProducerEmittedInvalidEvent` do. Invalid emissions join the
   structured error cascade (§Topology patterns) rather than living
   in an off-log annex.

2. **Sequence + append.** Assign the next sequence number N; append
   the event to the log.

3. **Update Views, synchronously.** View state is now as-of-N. The
   writer is the only thread touching Views, so there is no concurrent
   update.

4. **Evaluate Routes against event N.** Matching Routes stage their
   messages now. This is before Predicate evaluation in step 5 — a
   Trigger fired by event N can see messages staged from event N.
   (The Retry pattern relies on this: a Trigger on `ProducerFailed`
   reads the failure-reason message a Route staged from the same
   event.)

5. **Evaluate Predicates** in registration order against the
   as-of-N snapshot. Every predicate in this step sees the same
   snapshot: Views as-of-N, staged messages as of step 4. For each
   true predicate, the Trigger fires: `input_builder` runs now,
   against that same snapshot; the resolved input is recorded in a
   `TriggerFired` control-plane event; the Producer task is
   scheduled. The `TriggerFired` event is *not* appended inside this
   step — it is placed on the **control queue**.

6. **Drain the control queue.** Each queued control-plane event
   (`TriggerFired`, `ProducerStarted`, `InjectionApplied`, …) runs
   its own full append cycle — seq N+1, N+2, … — in FIFO generation
   order, before any further payload event is admitted. Cascades (a
   Predicate matching `TriggerFired` firing another Trigger) are
   therefore ordered, recorded, and each step of the cascade is its
   own atomic cycle. Reentrant appends from inside step 5 are
   prohibited; everything queues.

### Why this is consistent

Within a cycle, every Predicate and every `input_builder` sees one
defined snapshot. Cascade order is total and recorded. Resolved
inputs are deterministic functions of (snapshot, staged messages) and
are carried in `TriggerFired` events, so Level 2 replay reconstructs
not just that a Trigger fired but exactly what its Producer was given
— across implementations, because there is now only one legal
interpretation.

Admission order is the scheduling nondeterminism, and it is recorded.
Which Producer's emission wins admission next is a race; sequence
numbers record the outcome. This is precisely why Level 2 replay
works and why Level 3 for concurrent stochastic Producers requires
substitution (see §Replay).

### Why one bus, not many channels

Alternatives considered:

- *Point-to-point channels* (KPN-style): every Producer pair that
  communicates needs its own channel. N² wiring. Channel topology has
  to evolve when Triggers spawn new Producers.
- *Mutable shared state* (LangGraph-style): one global state blob,
  mutated by each node. Concurrency invariants are hard to reason
  about, and replay is incomplete because mutations aren't ordered.
- *Per-stage queues* (SEDA-style): each stage has its own input and
  output queues. Works for static pipelines, doesn't support dynamic
  spawn or arbitrary subscription.

A single totally-ordered bus collapses these into one place: events
live here, total order lives here, replay log lives here,
coordination for any number of Producers lives here.

### Persistence

Per-run by default — the bus lives in memory for the run, projected
to disk for replay. A persistent bus across runs is opt-in for
cross-run pattern work. In the persistent opt-in,
`ProducerId.instance_id` is unique only within a run; a run-id prefix
is required for cross-run uniqueness.

## Substrate composes with itself

A substrate instance is itself a Producer. It takes typed input, runs
an embedded substrate with its own internal bus and topology, and
emits the embedded run's events back onto the outer bus — but only
the events the embedded Producer kind has declared in its **export
map**.

The export map is part of the embedded substrate Producer's kind
declaration: a typed mapping `{inner event kind → outer event
schema}`. Only mapped kinds cross the boundary; they are translated
at the boundary and validated by the outer bus's append cycle like
any emission. Default export: the inner `RunFinalised` payload only.
Inner control-plane events (`TriggerFired`, `ProducerStarted`, …)
never cross unless explicitly mapped.

The inner substrate remains a black box presenting `start(input) →
AsyncIterable[Event]`; the export map is the typed face of that
contract. Backpressure cascades naturally: a congested outer
admission queue blocks the substrate Producer's outward emissions at
its boundary. The inner substrate isn't forced to slow internally; it
gets throttled at its export point.

Recursive composition: a code-writing topology can be wrapped as one
Producer in a larger pipeline. An ensemble-with-adjudicator can be a
substrate Producer that takes a task and emits a single answer.
Substrates wire together via typed event payloads; text is the common
case but any typed payload works.

## Vocabulary discipline

The substrate's vocabulary is deliberately not anthropomorphic, and
each term is chosen to carry the meaning of what it does rather than
to label a concept.

- *Producer*, not *speaker / actor / agent / participant / voice*.
- *Bus*, not *conversation / transcript*.
- *Predicate*, not *cue*.
- *Trigger*, not *spawn / handoff / activation*. A Trigger is a thing
  that fires when a condition holds — the word means what it does.
- *Topology*, not *cast*.

Application topologies that happen to be conversations do not get a
bespoke vocabulary. Two LLMs conversing are two Producers; the runtime
does not introduce *speaker* or *voice* concepts to flatter the
application.

## Non-goals

The substrate doesn't bake in any of the following. Every one of them
is buildable as a topology on top of the substrate; the substrate
just doesn't help you do them and doesn't pretend to know what they
mean.

- **No agent runtime baked in.** Producers have no runtime-level
  identity, lifecycle, planning, or goal state. *Build it on top:*
  an agent topology uses Producer kinds and event flows to express
  identity, planning, and goals.
- **No conversational orchestration baked in.** The runtime has no
  concept of turns, politeness, repair, or talking-past. *Build it on
  top:* a conversation topology uses Triggers with chunk-boundary
  predicates on each Producer's buffer; repair, scoring, and
  common-ground are auxiliary Producers wired as instruments.
- **Not a chat framework.** The bus is a typed event log, not styled
  dialogue. *Build it on top:* an application that wants chat UI
  renders the bus as chat downstream.
- **No DSL for pipelines.** Topology is host-language code.
- **No opinion about prompt construction.** A Producer's input is
  built by an application-layer function before the Producer starts;
  the substrate doesn't know what a prompt is.
- **Not a verification framework.** The substrate doesn't know what
  "verified" means. *Build it on top:* checks are Producers that emit
  typed events; Predicates gate on those events.
- **Not LLM-specific.** Producers may be LLMs, classical ML models,
  deterministic transforms, simulators, sensors, or anything with
  typed-input streaming-event-output shape.
- **Not Producer-trusting.** The substrate validates every emission
  against the Producer kind's declared event schema at the bus
  boundary. Untrusted sources are first-class.

## The primitives

Eight.

### 1. Producer

Typed input → async stream of typed events. The runtime calls
`start(input) → AsyncIterable[Event]` and consumes events until the
Producer completes, fails, or is cancelled.

**Input immutability is a formal contract.** A Producer's input is
sealed at instantiation time — when the Trigger's `input_builder`
returns. No running Producer's input can be mutated by Routes, other
Producers, or the runtime after `start()` is called. Routes stage
messages for *future* instantiations, never for running ones.

Producers are identified by a typed `ProducerId` with kind metadata,
not free strings. Each Producer kind declares the event schemas it
can emit; the bus validates every emission against those schemas at
the bus boundary.

### 2. Event

Append-only typed record with `ProducerId`, kind tag, payload, and a
**bus sequence number** (the event's logical position in the bus
total order). A run-monotonic wall-clock timestamp accompanies each
event as supplementary metadata but is not the event's identity.

Bus sequence number establishes total order and is what Predicates
and Views reason over. Wall-clock timestamp is supplementary.

### 3. Bus

The runtime's coordination point. Memory model and append cycle are
described in §The bus.

### 4. View

A deterministic projection over the bus. Examples: "accumulated text
payload from Producer P," "all events of kind K since sequence number
N," "count of events matching predicate Q." A buffer — accumulated
payloads from one Producer — is the most common View.

Views are materialised incrementally inside the append cycle's step 3,
synchronously with sequence number assignment, before any Route or
Predicate evaluates. A Predicate evaluated at sequence number N sees
a View that reflects all events with sequence number ≤ N. Predicates
never see partial state from concurrent appends.

### 5. Predicate

A cheap deterministic gate over Views and events, expressed as a
host-language callable. Predicates run on every relevant bus append,
so they must be O(1) or near it. Expensive semantic checks are
Producers that emit typed events; Predicates gate on those events.

The runtime enforces a per-call budget. A Predicate that exceeds the
budget is **quarantined**: the runtime stops consulting it. The
quarantine decision is itself a control-plane event
(`PredicateQuarantined`) — sequence-numbered, on the log, matchable
by other Predicates. Quarantine is consequential the same way a
termination signal is: it is an event, and the topology (via a
Trigger or a TerminationPolicy callback) decides what it means —
escalate, pause-await-input, finalise. Silent enforcement is not an
option; replay reconstructs the runtime's enforcement decisions.

Taxonomy:

- *Event-local*: matches a single just-appended event.
- *Buffer-local*: a View of a single Producer's stream crosses a
  threshold.
- *Bus-view*: a View over multiple Producers ("at least three
  candidates have emitted final answers").
- *Composite*: boolean combination of the above.
- *Externalised*: gates on a derived event emitted by an auxiliary
  Producer ("the scorer Producer emitted score > 0.8").

### 6. Trigger

The substrate's mechanism for creating Producers. A Trigger is
`(predicate, producer_factory, firing_policy, input_builder)`.

When the predicate holds against current bus state (the as-of-N
snapshot from step 5 of the append cycle), the Trigger fires:
`input_builder` runs against the same snapshot, the resolved input is
recorded in a `TriggerFired` control-plane event, and the Producer
task is scheduled. The `TriggerFired` event is enqueued on the
control queue; it drains in step 6 with its own full append cycle.
This makes cascade order total and recorded.

A Trigger's predicate may match events from any Producer in the run,
including descendants of the Trigger's own previous firings.
**Topology depth is unbounded.** Recursive decomposition,
dynamic-programming patterns, and arbitrary recursive composition fall
out directly. No per-depth Trigger registration is required.

Firing policies:

- *Once*: first satisfaction fires; further satisfactions ignored.
- *PerEvent*: each newly-satisfying event fires the Trigger once.
- *PerKey*: keyed firing; one firing per distinct key extracted from
  the matching event/View.
- *WhileTrue*: continuous firing while the predicate holds, with
  optional cooldown.

**Cooldown is logical by default.** Measured in append cycles
(sequence numbers): "fire at most once per K appends matching the
predicate's subscription." Deterministic and replayable at every
level the run otherwise supports.

**Wall-clock cooldown is opt-in and demoting.** A topology that
declares a wall-clock cooldown on any Trigger is flagged at
registration; the run's replay ceiling drops to Level 3(b)
(substitution required) and the flag appears in the run's metadata.
Operational expectations are set by the log, not by folklore.

**Divergence is the topology author's problem.** A Trigger whose
predicate is permanently satisfied by the events its own firings
produce will fire unboundedly. The substrate provides the tools to
prevent it (firing policies, keyed deduplication, TerminationPolicy)
but does not detect it.

### 7. Route (Injection)

Rule for incorporating typed events into the inputs of future
Producer instantiations. A Route is `(source_predicate,
target_input_slot, transform)`. Push by default: matching source
events produce typed messages that the runtime stages in step 4 of
the append cycle; the next Trigger evaluated in the same or later
cycle whose target slot matches reads the staged messages from its
`input_builder`. Pull is available: an `input_builder` may explicitly
query a Route when assembling input.

**Route timing (Decision #8, restated).** A Route's staged message is
visible to Trigger firings evaluated in the same append cycle as the
staging event, and all later cycles. The Retry pattern's "enriched
via a Route that injects the failure reason" works as written — no
one-event delay. Routes are never retroactively applied to already-
started Producers; they only influence future instantiations.

### 8. TerminationPolicy

A host-language callback that interprets termination signals
(Producer-emitted events of a designated kind), Producer completions,
failures, cancellations, predicate quarantines, and quiescence into
one of: cancel-others, let-finish, finalise-run, pause-await-input,
continue.

**Quiescence, defined.** No running Producers; admission queue empty;
control queue empty; no Trigger whose predicate is true-now and
unfired under its firing policy; no pending wall-clock cooldown
firing. With logical cooldowns the last clause is vacuous (no future
appends → no maturation); with wall-clock cooldowns the
TerminationPolicy receives pending timers as part of the quiescence
input. A topology using only logical cooldowns can use quiescence-
with-watchdog without worrying about scheduled-but-not-fired
Triggers.

**Scoping.** Per-run and per-Producer policies coexist via
composition: per-Producer policies are evaluated first and may emit
decisions for the Producer's subtree; the per-run policy then
interprets the aggregate. If the per-run policy emits finalise-run,
it overrides all per-Producer policies.

**Cancellation propagation.** Flat by default — cancelling a Producer
does not automatically cancel its Trigger descendants. Subtree
cancellation is an opt-in named composition in the standard policy
recipe book. The default prevents surprising cascade cancellations
in fan-out topologies.

The substrate ships standard policies (cancel-all-others, let-finish,
quiescence-with-watchdog, threshold-count, all-completed) as named
functions, but the contract is the callback, not the recipe set.

Side-channels, adjudicators, repair detectors, scorers, typecheckers,
parsers, simulators, and human input streams are **not primitives**.
They are topology patterns built from Producer + subscription View +
Route.

## Lifecycle and control-plane events

The runtime emits the following event kinds in addition to
producer-defined payload kinds. Every kind in this table is
sequence-numbered, on the log, replay-visible, and matchable by
Predicates.

| Kind | Meaning |
|---|---|
| `RunStarted` | Frame 0 of every record. Carries the topology manifest: registered Producer kinds with schema descriptors, Trigger/Route/View/policy identifiers, cooldown flags, baseline metadata. The causal root every initial Producer attributes to. |
| `TriggerFired` | A Trigger's predicate was satisfied; identifies trigger, factory, key, resolved input. Enqueued on the control queue at end of step 5; appended in step 6. |
| `InputBuildFailed` | A Trigger's `input_builder` raised; identifies trigger, firing key, error. The firing does not produce a Producer; the failure is on the log instead of silent. |
| `ProducerStarted` | Producer task began running. |
| `ProducerEmittedInvalidEvent` | A Producer emission failed schema validation; raw payload preserved inside, typed reason attached. Sequence-numbered, on the log, matchable. |
| `ProducerCompleted` | Producer's stream exhausted normally. |
| `ProducerFailed` | Producer errored; payload includes error. |
| `ProducerCancelled` | Runtime cancelled Producer per policy. |
| `InjectionApplied` | Route contributed typed messages to a Producer's input. |
| `PredicateQuarantined` | The runtime stopped consulting a predicate; identifies the predicate, its Trigger, measured budget violation, enforcement decision. |
| `TerminationMatched` | TerminationPolicy fired; identifies the policy decision. |
| `RunFinalised` | Run produced its final output. |

Application events emitted by Producers are *not* wrapped in a
control-plane kind. The kind namespace distinguishes runtime events
(`substrate.*` reserved prefix) from application events (user-declared
kinds); the act of being on the log after validation is what
"post-validation" means. Every event on the log carries a
`producer` field identifying its emitter (or null for runtime-emitted
events).

## Topology patterns

Side-channels, adjudicators, repair detectors, scorers, typecheckers,
parsers, simulators, and human input streams are not primitives.
They are topology patterns built from Producer + subscription View +
Route. Below are patterns that come up constantly and that the
primitives already cover.

**Retry.** A Trigger with predicate on `ProducerFailed` events and
firing policy `PerKey` (keyed on the failed Producer's kind) fires a
replacement Producer with the same input, enriched via a Route that
injects the failure reason. Retry limit is enforced by a predicate
that counts retry attempts from the bus View. Routes-before-Triggers
in the append cycle (step 4 before step 5) means the replacement
Producer's `input_builder` sees the failure-reason message staged
from the same event that fired the retry. No one-event delay.

*Inner retries do not amplify with outer retries.* If a Producer
runs its own internal retry loop (e.g. an LLM call that re-prompts
with build-error context until a validation passes or its budget K
is exhausted), it must not surface those failures as `ProducerFailed`
events while still inside the loop — that would let any outer retry
Trigger watching the same predicate re-spawn the Producer and the
inner K retries would multiply by the outer count. A Producer that
exhausts its own internal retry budget emits a terminal event of a
dedicated kind (e.g. `RetryExhausted`) carrying the failure context.
That event is not matched by retry Triggers; the outer topology
decides separately whether to give up, escalate, or pause for human
input.

**Halt with resume condition.** Some topologies need to pause and
wait for external input — a human approves a plan-mode decision, a
file is deposited at a known path, a configuration value is updated.
A TerminationPolicy decision of `pause-await-input` is a distinct
state alongside `cancel-others` / `let-finish` / `finalise-run`; the
policy emits a `TerminationMatched` event whose payload includes a
typed `resume_condition` naming exactly what would unstick the run.
Observers consuming the bus see the wait state and the resume
condition simultaneously. When the resume condition is met (the
external event arrives), a Trigger on that event fires the
continuation Producer.

**Progress gating.** A predicate over a Bus-view — "at least N
candidates have emitted final-answer events" — fires correctly
because the bus is totally ordered and Views are updated synchronously
before predicate evaluation. There is no race between Producers to be
counted. "Wait for all currently-running Producers of kind K" is the
predicate "count of `ProducerCompleted` events for kind K equals
count of `ProducerStarted` events for kind K."

**Cultured-starter sessions.** Persistent-bus topologies often want
new runs to inherit context from prior runs rather than bootstrapping
from scratch — the project's vocabulary, prior decisions, accumulated
state. A `CulturedContext` Producer started at run init reads a View
over the persistent bus and emits `ProjectContext` events; downstream
Producers' `input_builder`s route those events into their inputs.
"Bootstrap a fresh session" collapses to "read prior bus state and
start emitting." The pattern is the substrate equivalent of a
sourdough starter — context is cultured, not snapshotted.

**Structured error cascade.** Every Producer failure has a typed
upward path on the log. `ProducerFailed`, `ProducerEmittedInvalidEvent`,
`PredicateQuarantined`, and dedicated terminal kinds like
`RetryExhausted` are all sequenced events that downstream Triggers or
TerminationPolicy callbacks match on. The decision (retry, escalate,
surface via pause-await-input, finalise) is itself recorded as
`TerminationMatched` or a follow-on `TriggerFired`. Topologies should
not silently swallow failures or invent ad-hoc error handling — every
failure mode has a designed upward path, and the bus records the
decision. The cycle's step 1 (invalid emissions become log events)
and the predicate quarantine event (§5) strengthen this for free:
schema violations and runtime enforcement decisions join the cascade
rather than disappearing.

None of these patterns require a new primitive.

## Replay semantics

The bus is the run record. Replay reads it and reconstructs what
happened. Three levels:

**Level 1 — Event replay.** Reconstruct all Views, displayed/output
state, and any deterministic derivation from the recorded event log.
Always possible for any recorded run.

**Level 2 — Schedule replay.** Reconstruct Trigger, injection, and
termination decisions from recorded control-plane events. Always
possible given Level 1, because the runtime's decisions are themselves
recorded events. Resolved inputs are carried in `TriggerFired` events,
so this includes the exact input each Producer was given. This is
the substrate's primary replay guarantee.

**Level 3 — Deterministic re-execution.** Re-run the topology and get
equivalent behaviour.

- *Level 3(a) — Native re-execution.* Possible if every Producer's
  output is reproducible (seeded deterministic Producers, recorded
  randomness) and no Trigger uses wall-clock cooldowns. Substrate
  flags the latter at registration.
- *Level 3(b) — Substitution re-execution.* Re-run with every
  Producer's emitted events substituted from the recorded log. Always
  possible given Level 1; this is what replay infrastructure for
  stochastic Producers uses.

Wall-clock cooldowns drop the achievable ceiling to 3(b) only. Logical
cooldowns preserve 3(a) where Producer determinism allows.

The trace/replay UI is not part of the substrate. It is a separate
tool that reads the persisted event log.

## Conformance

The append cycle, admission queue, and lifecycle semantics described
above are testable. A minimal kernel implementation
(`substrate_v14_kernel.py`) re-runs the v13 failure cases as
conformance checks:

1. The Retry pattern receives the failure reason from the triggering
   event (no one-event delay).
2. A topology with cascading Triggers has exactly one legal outcome
   regardless of implementation choices about when `TriggerFired`
   becomes visible.
3. Six payload appends through a bound-5 admission queue complete
   without deadlock while the log retains all events.
4. An invalid emission appears on the log, sequence-numbered, and
   fires a Predicate registered against `ProducerEmittedInvalidEvent`.

A v14 implementation that passes these four checks has implemented
the cycle correctly. Additional conformance tests will follow as the
spec evolves.

## What this enables

These are worked topology examples, not an exhaustive catalogue. They
compose with each other — a code-team topology can include an
ensemble within one of its writer slots; a conversation can be
wrapped in an adversarial pair; a simulation can include LLMs as some
agents and deterministic transforms as others.

**Code synthesis with overlap.** A writer Producer streams; a
tree-sitter Producer wired to a View on the writer's buffer emits
typed AST events; a typecheck Producer is fired by a Trigger the
moment a complete top-level declaration lands; a test-runner Producer
is fired once a function is fully written. Writer still streaming,
typecheck already running, test-runner already loading. Wall-clock
latency drops because nothing is sequential that doesn't have to be.

**Heterogeneous pipelines.** An LLM Producer emits a draft; a
sentiment-analyzer Producer (a small classical ML model, not an LLM)
reads the draft and emits typed sentiment events; a classifier
Producer reads the sentiment events and emits a typed routing
decision; a Trigger on the routing decision fires one of several
downstream LLM Producers with the original draft and the
classification routed in.

**Ensemble generation.** N cheap weak Producers run the same input
with different decoding seeds, all streaming into one Bus; an
adjudicator Producer is fired when a Bus-view predicate ("≥3
final-answer events") is satisfied.

**Pair coding.** A Navigator Producer subscribed to a View of the
Driver's buffer emits typed suggestion events; a Route stages
suggestions for the Driver's next chunked instantiation.

**Code teams.** Writers per module fired by Triggers on
`task_assigned` events from a Planner Producer; reviewer Producer
fired by a fan-in Trigger over per-module completion events;
revisions retried via PerEvent Triggers with reviewer notes routed
into the next writer instantiation.

**Adversarial pairs.** Writer and vulnerability-finder Producers
stream concurrently from t=0; finder reads the writer's View and
emits typed challenge events; a Trigger with predicate on challenge
events fires a refinement Producer.

**Game-theoretic simulation.** Two Producers play iterated prisoner's
dilemma. Each reads its View of the opponent's prior moves and emits
a typed move event. A payoff-calculator Producer (deterministic) reads
both move events and emits a payoff event. A Trigger on payoff events
fires the next round of both Producers with the updated history
routed in. A TerminationPolicy ends the run after N rounds or on a
convergence condition.

**Population simulation.** A population of stochastic agent Producers
started at t=0, each emitting typed action events; a world-state
Producer subscribed to all actions emits typed world-state events;
agents' next-step inputs are routed from world-state updates. The
substrate runs the whole simulation as a streaming dataflow; the bus
is the simulation log.

**Streaming research synthesis.** M retrievers stream candidates
concurrently; a synthesizer Producer fired at the first
relevance-predicate cross from any of them; a fact-checker Producer
subscribed to the synthesizer's View routes corrections into the
synthesizer's next instantiation.

**Recursive decomposition.** A Planner emits N `subtask` events; one
Trigger with PerEvent firing fires N Solver Producers; each Solver
may itself emit further `subtask` events that the same Trigger
matches (no depth check), giving arbitrary-depth recursion without
per-depth rules.

**Tool-using chains.** Tools are first-class Producers on the Bus,
not synchronous subroutines. An "agent loop" is a chain of (Model
Producer → Tool Producer → Model Producer → …) instantiations gated
by event-local predicates; each model call is a discrete,
independently replayable Producer.

**Conversation.** Two LLM Producers fired by alternating Triggers
with chunk-boundary predicates on each other's buffers. The
TerminationPolicy interprets a convergence signal as
cancel-all-others + finalise. Conversation is one topology — no
special vocabulary.

**Steganographic capture.** A Producer that emits visual output (a
rendered UI, a screenshot, a diagram) embeds structural metadata in
the pixels themselves — LSB encoding across the frame, a QR code at
fixed coordinates, an RGB data strip in a known region. A Decoder
Producer subscribed to the visual output decodes the embedded payload
and emits typed structural events onto the bus. The bus carries both
modalities: raw image bytes for human inspection, structured events
for downstream Predicates and Triggers. The substrate is
payload-agnostic; this falls out without modification.

These examples are not exhaustive — they are building blocks, and the
substrate composes. A code-team topology can include an ensemble in
one of its writer slots. A conversation can be wrapped in an
adversarial pair. A simulation can include LLMs as some of its agents
and deterministic transforms as others. A TerminationPolicy can be
built from smaller policies; a heterogeneous pipeline can route into
a recursive decomposition. Composition is the normal usage pattern.

## Where this points

These directions are not in scope for the substrate spec but become
tractable because of the primitives. Naming them because they're what
makes the substrate interesting beyond "a better orchestrator for LLM
agents." Anyone can slice LLMs different ways; the directions below
are the territory existing tools structurally don't reach.

**Speculative execution with rollback.** Multiple Producers run
concurrently on the same input (best-of-N is one form; the general
case is any K-way branching). The append-only bus preserves every
branch's events. A Predicate gates which branch advances; the losers'
events are not deleted but preserved in the log. The substrate makes
it tractable to rewind to any branch point, fork the topology, and
replay forward with alternate parameters or alternate Predicates.

**Cross-run delta predicates.** A Predicate that fires not on the
current bus state but on the delta between this run's bus and a prior
run's bus on the persistent store. "This SignalReport diverges from
last week's SignalReport for the same task by more than threshold X"
is expressible as a Predicate over two Views (current bus, prior
persistent bus). Drift detection and longitudinal anomaly detection
become first-class behaviours rather than bolt-on tooling.

**Adversarial cross-instantiation learning.** Beyond the basic
adversarial-pair pattern: two Producers run concurrently from t=0;
one writes, the other attacks. The attacker reads the writer's
buffer (View) and emits typed challenge events. Routes inject those
challenges into the writer's *next* instantiation; the writer learns
from the adversary across instantiations. Input immutability is what
makes this safe — the attacker can't corrupt the running writer,
only influence the next one.

**Multi-modal topologies.** A topology where Producers are a mix of
LLMs, classical ML models, deterministic transforms, simulators,
sensors (camera frames, microphone audio), human input streams,
external API clients, runtime metric collectors. The Producer
protocol is shape-agnostic. Concrete: a code-writing topology whose
artifact-grader includes a runtime sensor Producer monitoring actual
CPU and memory of the running program, with Predicates that gate on
observed performance.

**Meta-orchestration (topology-as-output).** A Producer whose emitted
events are a typed Topology specification. One substrate run
generates a tailored topology for a specific task; a second substrate
run executes that generated topology. Treatment runners (the
bench-orchestrator pattern from operations research and Factory v0's
experimentation model) are one instance. The fractal-composition
decision (#24) is what makes this clean — the generated topology is
a Producer in the outer substrate, with its own typed export map.

**Self-modifying topologies.** A Producer subscribed to past-run bus
events observes which Predicates fire most usefully, which Triggers
actually drove forward progress, which Routes had high
signal-to-noise. It emits proposed-topology-mutation events
(`AddTrigger`, `RetireProducerKind`, `RouteChange`). The Architect
(a pause-await-input policy) accepts or rejects. Accepted mutations
bump the topology's structure; future runs use the evolved topology.

**Federated substrates.** Two Architects' substrates communicate via
signed event handoffs over a network. The fractal-composition
decision generalises from local nested instances to remote ones: a
substrate Producer is a remote substrate. Bus-boundary validation
covers what's needed — every incoming event from the remote substrate
is validated against the local Producer kind's declared schema
before entering the local bus. The export map types the boundary;
inner control-plane events don't cross unless explicitly mapped.

**Time-travel debugging.** The append-only bus plus the three-level
replay framing means you can wind back to any past sequence number,
inspect bus state, fork the topology at that historical point, and
replay forward with alternate parameters or alternate code.
Retroactive grading — applying an evolved assertion DSL to a past
run's events and seeing the new grade — becomes structural.
Post-mortems become reproducible rather than narrative.

**Steganographic state-hash propagation.** Every event payload
carries a deterministic hash of the View state the Producer saw when
it ran. Downstream consumers verify against their own View's hash;
disagreement surfaces concurrent-mutation bugs at the event boundary
rather than as silent corruption.

These directions exploit features the obvious LLM-orchestration use
case doesn't lean on: concurrent overlap, persistent buses across
runs, recursive Triggers, fractal composition, immutable input,
untrusted Producers, total ordering with sequence numbers,
deterministic Views across the cycle. The substrate's value shows
most in topologies that need these properties — which is exactly the
territory existing orchestration tools don't reach.

## Problems this solves

- **Sequential bottlenecks in tight-loop architectures.** Typecheck
  waits for full code; test waits for full typecheck. Each stage fires
  at the earliest predicate it can satisfy, so they overlap.
- **One strong model with no leverage from weaker models.** Express
  this as an ensemble + adjudicator topology instead of having it
  baked out of the architecture.
- **One prompt, one model, one shot.** Multiple Producers contribute
  to one Bus over time.
- **All computations being the same kind of thing.** A Producer is
  any typed-input streaming-event-output computation: LLM, ML model,
  deterministic transform, simulator, external process.
- **Recursive decomposition.** Planners firing solvers firing solvers
  via Triggers whose predicates match events at any depth.
- **Static topology graphs.** New Producers are created at runtime as
  predicates are satisfied. The graph evolves while the run is
  running.

## Costs and limits

- **Predicate authoring is a new design surface.** Bad predicates
  fire Triggers too early or too late. The predicate taxonomy and
  the progress-gating pattern are guards.
- **Backpressure has to be sized at the admission queue.** The
  admission queue's bound is the credit pool. Implementation picks
  the bound; LLM Producers run at token rates and won't saturate,
  but deterministic Producers (parsers, simulators) can outrun the
  queue.
- **Log growth is unbounded per run.** The log is append-only and
  monotonic. The implementation owns spill of cold segments to disk;
  the hot path stays in RAM.
- **Auxiliary-Producer cost is unbounded by default.** Each is an
  extra invocation; topologies that wire many can blow cost out.
  Firing policies are the throttle.
- **Debugging a topology is harder than a synchronous chain.** N
  Producers + K Routes + Trigger timing. Replay + the lifecycle event
  stream is the answer.
- **Replay levels are honest.** Level 3(a) for stochastic Producers
  requires seeded determinism. Wall-clock cooldowns drop the ceiling
  to 3(b). Substitution is always available.
- **LLM context is bound at instantiation.** Routes inject into
  future instantiations, not running Producers. "Live" interactions
  are chunked instantiations or kill-and-respawn.
- **Trigger divergence is the topology author's responsibility.** A
  self-feeding Trigger fires unboundedly if not constrained by firing
  policy, keyed deduplication, or TerminationPolicy.

## Relation to prior work

The substrate draws on several traditions. The comparisons below name
the closest kin and what's deliberately different.

**Linda / tuple spaces** (Gelernter, 1985). The closest kin v13
didn't cite: coordination through a shared associative space,
processes spawned via `eval`, matching via templates. Substrate is,
roughly, Linda with a total order, typed schemas, sealed inputs, and
a replay log. Linda's tuple space is the lineage of "shared
coordination point"; Substrate adds the discipline that makes
distributed and replayable execution tractable. The literature on
distributed tuple spaces is directly relevant to the
federated-substrates direction.

**Complex Event Processing** (Esper, Flink CEP). Twenty years of the
Predicate taxonomy — event-local, windowed, cross-stream composite
patterns firing actions — including the lesson Substrate re-derives:
pattern matching must be cheap and semantic judgment must live
elsewhere. CEP's window-and-key machinery is the right reference for
`PerKey` firing policies rather than re-deriving from scratch.

**Kahn Process Networks (KPNs)** (Kahn, 1974) are deterministic
dataflow networks where processes communicate via blocking reads on
FIFO channels. KPNs guarantee that given a fixed input history, every
process always produces the same output. Substrate departs in two
ways: determinism is not required (stochastic Producers are
first-class), and the communication model is a shared bus rather than
point-to-point channels. Multi-source predicates — "fire when at
least three Producers have emitted final answers" — require no extra
machinery in Substrate; KPNs need explicit merge processes.

**Naiad / Timely Dataflow** (Murray et al., 2013) introduced logical
timestamps and progress tracking for cyclic dataflow without global
synchronization. Naiad's frontier — the set of timestamps beyond
which no more messages will arrive — lets iterations know when an
iteration is complete. Substrate's Triggers do similar work with
event predicates and firing policies. Tradeoff: Naiad's progress
tracking is formally verifiable; Substrate's predicate model is more
expressive and composable, but the topology author has to reason
about predicate satisfaction conditions. Naiad also requires a static
dataflow graph; Substrate's Triggers create new Producers
dynamically, with `TriggerFired` events on the bus recording the
graph's evolution.

**SEDA (Staged Event-Driven Architecture)** (Welsh et al., 2001)
decomposes applications into pipeline stages connected by bounded
queues, with adaptive thread pools per stage. SEDA stages have fixed
wiring; Substrate stages are created dynamically. SEDA focuses on
load-conditioned concurrency; Substrate focuses on predicate-driven
topology evolution. The shared philosophy — isolate stage-to-stage
coupling behind queues — generalises in Substrate to making the bus
the universal coupling point.

**Temporal** provides durable, replayable workflow execution via
event sourcing. Substrate's bus serves the same archival function.
Temporal's execution is sequential (one workflow coroutine at a
time); Substrate's is concurrent (N Producers running simultaneously).
Temporal's signals are pushed into running workflows; Substrate
Routes stage messages for future Producer instantiations because
running Producers have immutable input. Temporal's replay is stronger
than Substrate's Level 3 because Temporal requires deterministic
activities; Substrate honestly bounds replay levels for stochastic
Producers.

**Reactive Streams / Rx** define Publisher, Subscriber, Subscription,
and Processor with credit-based backpressure on point-to-point flows.
Substrate has a shared admission queue rather than point-to-point
subscriptions; the credit-pool analogy attaches to the admission
queue, which is the thing that actually behaves like one — bounded,
drained by a single writer, blocking submissions when full. The
Reactive Streams credit protocol is a reasonable model for sizing
the admission queue's bound. The per-subscription "slow consumer"
concept doesn't apply because there are no per-subscription consumers
in Substrate — Predicates are required to be O(1), Routes are reads,
Triggers create new Producers. Different shape for a different
architecture.

*Footnote on π-calculus.* π-calculus provides a formal model for
processes communicating via named channels, with channel names as
first-class values. Substrate has no channels, no channel-passing,
no reduction semantics; the comparison decorated rather than informed
the design and is retained here only as acknowledgement.

## Decisions made

1. **Public API.** The substrate is importable as a library. Any CLI
   is one consumer.
2. **Producer identity.** Typed `ProducerId` with kind metadata:
   `{kind: str, instance_id: str, parent_id: ProducerId | None,
   metadata: dict}`. `instance_id` unique within a run; ancestry
   reconstructable from `TriggerFired` events.
3. **Bus total ordering.** Concurrent appends serialized at the single
   writer. Chosen over partial ordering because total ordering is
   simpler, replayable without ambiguity, and the bus is not the
   throughput bottleneck.
4. **Bus persistence.** Both supported. Per-run default; persistent
   opt-in.
5. **Predicate language.** Host-language callables. O(1) or near-O(1)
   budget enforced by the runtime; violations are recorded as
   `PredicateQuarantined` events on the log.
6. **Input immutability.** Formal contract on Producer. Running
   Producers cannot receive injected messages mid-stream. Routes
   operate at instantiation boundaries only.
7. **Route push vs. pull.** Both. Push by default.
8. **Route timing.** Staged messages are visible to Trigger firings
   evaluated in the same append cycle as the staging event, and all
   later cycles. (Revised from v13: the retry pattern now works as
   written, no one-event delay.)
9. **Cancellation propagation.** Flat by default; subtree
   cancellation is an opt-in named composition.
10. **TerminationPolicy form.** Arbitrary host-language callbacks.
    Closed enum of named recipes ships on top as a convenience.
11. **Topology patterns (retry, progress gating, cultured starter,
    structured error cascade, halt with resume condition).** Named
    as patterns, not promoted to primitives.
12. **Trace/replay UI.** Separate tool reading the persisted event log.
13. **Application terminology in conversation topologies.** Producers
    stay Producers.
14. **Top-level preset construct.** None. Named topologies are factory
    functions in a registry.
15. **CLI surface.** `--topology <name>` against a registry plus
    `--topology-module path/to/mod.py` for user-written Python.
    Per-topology flags accepted by the topology factory.
16. **Documentation splitting.** Eventually three artifacts (concept
    note, runtime primitive spec, current-code migration note). One
    unified document while the runtime spec hardens.
17. **Dynamic topology / recursive Triggers.** Arbitrary depth. A
    Trigger's predicate may match events from any Producer including
    descendants of its own previous firings.
18. **Producer scope.** Not LLM-specific.
19. **TerminationPolicy composition.** Policies compose via the host
    language. Per-Producer and per-run policies coexist via scoping.
20. **Route aggregation.** Routes are one-event-in / one-message-out.
    Aggregation is a Producer pattern.
21. **Event encoding for the persistent-bus opt-in.** JSONL default.
    Pluggable for binary formats.
22. **Event identity.** Bus sequence number, not wall-clock timestamp.
23. **Bus-boundary validation is mandatory.** Every Producer emission
    validated against the Producer kind's declared event schema.
    Invalid emissions are wrapped as `ProducerEmittedInvalidEvent`
    control-plane events — sequence-numbered, on the log, matchable
    by Predicates. (Revised from v13: invalid emissions are no longer
    off-log.)
24. **Substrate composes with itself.** A substrate instance is a
    Producer. Substrates wire together via typed event payloads.
    Embedded substrate Producers declare an **export map** (`{inner
    event kind → outer event schema}`) as part of their kind
    declaration; only mapped kinds cross the boundary. Default export:
    inner `RunFinalised` payload only.
25. **Control-plane append semantics.** Control-plane events
    (`TriggerFired`, `ProducerStarted`, …) are enqueued on a control
    queue during the append cycle's step 5 and drained in step 6 with
    full append cycles in FIFO generation order. Reentrant appends
    from inside Predicate or `input_builder` evaluation are
    prohibited. This makes cascade order total and recorded.
26. **Admission queue.** Bounded submission queue ahead of the single
    writer is the backpressure mechanism. The log itself is
    append-only and grows monotonically per run; spill to disk is the
    implementation's responsibility. Views stay hot.
27. **Cooldown basis.** Logical (append-cycle-counted) by default,
    deterministic and replayable. Wall-clock cooldown is opt-in and
    drops the run's replay ceiling to Level 3(b); the flag is
    recorded in the run's metadata.
28. **Predicate quarantine.** A recorded decision, not a silent
    runtime mutation. `PredicateQuarantined` is a control-plane event
    on the log, matchable by Predicates and TerminationPolicy
    callbacks.

## Implementation-time choices

- **Concurrency model.** Pick the most appropriate runtime (asyncio,
  structured concurrency, alternatives). The substrate doesn't
  constrain this.
- **Single-writer queue with async handoff.** The model the spec's
  semantics assume. Producers submit emissions to a bounded admission
  queue; a single writer drains it and runs append cycles. This is
  the synchronisation point: validation, sequence assignment, View
  updates, Route staging, Predicate evaluation, and `input_builder`
  invocation all run inside the writer on each cycle.
- **Admission queue backpressure.** Use a standard, well-understood
  approach (bounded queue, credit-based per Reactive Streams) for
  sizing the admission bound. Don't invent.
- **Log spill.** When the hot tail exceeds an implementation-chosen
  threshold, older sealed segments spill to disk. The hot path never
  reads raw history; only pull-Routes, explicit historical queries,
  and replay touch spilled segments.
- **Predicate budget enforcement.** Timeout or instruction-count
  limit on Predicate evaluation. Violations emit
  `PredicateQuarantined`. The implementation picks the mechanism;
  the substrate's commitment is that violations are recorded as
  events.
- **Runtime validation library.** Pydantic, msgspec, or similar. The
  substrate's commitment is that validation happens.
- **Process locking on persistent buses.** When the bus is persisted
  across runs and lives at a known root, the runtime should acquire
  an exclusive file lock at that root before starting a run.
  POSIX `flock` is the standard mechanism; non-POSIX hosts fall back
  to PID files with stale-detection.
