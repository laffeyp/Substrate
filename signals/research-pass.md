# Substrate Vocabulary Session — Research Pass

*Academic + best-practices + the specs’ own cited prior art + an SDD-grammar re-derivation, run as a parallel subagent team (CT-1) before drafting the eleven layers. Each finding is genre-labelled. This document grounds the grammar decisions in `0.1-rationale.md`.*

## Strand: ONTOLOGY-LEARNING & GRAMMAR DESIGN best practices for a typed signal/event vocabulary (Substrate's 11-layer grammar)

- **Claim.** Cimiano's ontology-learning layer cake is a strict bottom-up dependency stack (terms -> synonyms -> concepts -> concept hierarchy -> relations -> relation hierarchy -> axiom schemata -> general axioms) in which the output of each lower layer is the input to the next; the upper layers are the least-developed and hardest.
  - *Evidence:* Survey literature (thinkmind, PMC) states the layers are 'designed such that results of lower layers serve as inputs to higher layers' and that 'much of the progress in ontology learning so far has concentrated on the lower levels... while relatively little attention has been paid to the automated identification of axioms.' The top two layers (axioms/rules) are 'the most challenging task, as in principle there is no limit on the type and complexity of axioms and rules to be learned'; axioms are 'often implicit and abstract' and 'developing axioms is also challenging for humans.'
  - *Genre:* peer-reviewed survey / academic figure references (Cimiano via secondary peer-reviewed surveys)
  - *Bearing on the grammar:* Confirms and grounds the PRINCIPLES.md claim (line 49) that Substrate's upper layers (5 State-Transition, 6 Runtime, 7 Evidence) saturate/underspecify first. The 11-layer stack should EXPECT sparse Layer 5-7 entries in 0.1.json and treat that sparseness as normal, not as a defect to be filled by inference. BOOTSTRAP Step 6's explicit 'Sparseness is OK' instruction is the correct posture. Axioms-are-hard-even-for-humans justifies routing Layer 5/7 gaps to the Architect as INVARIANT_PROPOSED / SEQUENCE_RULE_PROPOSED rather than agent self-authoring.

- **Claim.** The strict layered decomposition is itself a known failure mode: errors propagate upward and the rigid sequential split produces low-quality results because each layer inherits the noise of the layer beneath it.
  - *Evidence:* Cimiano (and co-authors) published a paper titled 'Ontology Learning from Text: Why the Ontology Learning Layer Cake is not Viable' (Int'l Journal of Signs and Semiotic Systems 4(2), 2015). The argument: 'splitting the tasks, as in Ontology Learning Layer Cake methods, results in low quality results, making the methods unviable' because the decomposition 'does not take into account the conditions of the problem, nor the quality of the results obtained.' Browarnik notes a 'low maximum F measure (probably below 0.6).'
  - *Genre:* peer-reviewed paper (the layer-cake's own originator arguing its limits)
  - *Bearing on the grammar:* Important corrective: Substrate borrows the layer-cake's DEPENDENCY ORDERING (BOOTSTRAP walks 0->1->2->...->7) but must avoid the cake's fatal flaw of treating each layer as a sealed automatic hand-off. Substrate's mitigation is already correct in PRINCIPLES line 47: when an upper layer reveals a lower-layer underspecification, the discipline LOOPS BACK and proposes the missing element rather than silently inferring it. This back-propagation (e.g. PAYLOAD_FIELD_PROPOSED back to Layer 0 via ENTITY_IMPLIED_BUT_UNNAMED) is precisely what makes Substrate's stack viable where the pure cake is not. Keep the human Architect in the loop at every layer boundary; that is the difference between the cake and Substrate.

- **Claim.** Unilateral schema/relation invention is the dominant failure mode when building structure from text with LLMs: models hallucinate relations not grounded in the source (e.g. inferring causation from mere co-mention). The mitigation that works is grounding extraction in a pre-built, supervised, iteratively-refined schema rather than letting the model invent the vocabulary during extraction.
  - *Evidence:* KG-construction literature: LLMs 'occasionally generate hallucinated relationships that are not grounded in the source text... a causal link between two entities that are merely co-mentioned.' Effective frameworks 'use a pre-built, iteratively refined schema to guide extraction, providing the LLM with a grounded type taxonomy and tag vocabulary rather than asking it to invent one,' and add 'multi-LLM consensus validation' and 'human-in-the-loop curation' where the LLM 'proposes category assignments' but grounding tools verify each identifier.
  - *Genre:* peer-reviewed / arXiv preprints (KARMA, Graph Judger, OntoKG) — mixed maturity, some preprint not yet peer-reviewed
  - *Bearing on the grammar:* Directly validates non-negotiable commitment 3 ('Workers cannot invent vocabulary'). The literature's 'propose, don't invent; Architect ratifies' pattern IS Substrate's supervised-grammar-evolution proposal taxonomy (the 8 *_PROPOSED kinds). Each proposal MUST carry a source citation (which doc, which sentence) precisely because the failure mode is ungrounded invention — citation is the grounding check. The reserved 'substrate.' lifecycle/control-plane kinds (e.g. substrate.ProducerEmittedInvalidEvent) must be transcribed VERBATIM from the spec, never paraphrased (InvalidEmission would be a hallucinated relation by another name). Keep the 13 kernel kinds in their exact spec PascalCase under the substrate. namespace.

- **Claim.** In DDD, the same surface term legitimately denotes different concepts in different bounded contexts (polysemy); a single unified domain model for a large system is not feasible, so contexts are split with explicit mappings.
  - *Evidence:* Fowler (canonical bliki): 'total unification of the domain model for a large system will not be feasible or cost-effective'; terms like 'meter' at a utility meant grid-connection, customer-relationship, or physical-equipment in different departments — 'polysemes' that 'create problems in precise software systems.' Each bounded context maintains its own ubiquitous language.
  - *Genre:* authoritative practitioner reference (Fowler bliki) + DDD reference PDF (Evans) — foundational, widely-cited, but not peer-reviewed
  - *Bearing on the grammar:* Grounds the TAG_SPLIT_PROPOSED evolution type and the Layer-0 ENTITY_MERGE_PROPOSED type. The PRINCIPLES.md example (PAYMENT_DECLINED in retail-checkout vs subscription-renewal) is textbook DDD polysemy. Reinforces non-negotiable: categories must align with ARCHITECTURAL BOUNDARIES (bounded contexts), NOT class/file names — Substrate's categories ARE its bounded contexts. When one surface term is found spanning two contexts, the agent surfaces TAG_SPLIT_PROPOSED; when one entity appears under different surface forms across docs (the conversation / ConversationSession / ChatThread example), it surfaces ENTITY_MERGE_PROPOSED for Architect reconciliation — never silent collapse.

- **Claim.** Domain/event names are conventionally past-tense {Entity}{Verb-past} because an event is something that has already happened; this is part of the DDD ubiquitous language and makes the semantics legible to engineers and domain experts alike.
  - *Evidence:* Microsoft .NET DDD/CQRS docs: 'The class name of the event should be represented as a past-tense verb... OrderStartedDomainEvent, OrderShippedDomainEvent.' Practitioner consensus (Alapont, eventsourcing.dev): canonical examples OrderPlaced, PaymentReceived, InventoryReserved, ShipmentDispatched; 'an Event is always something that has happened, and it should reflect this in its name being in the past tense.'
  - *Genre:* official vendor docs (Microsoft Learn) + practitioner blogs/community — convergent across genres
  - *Bearing on the grammar:* Validates Layer 1 (Lexical) form {ENTITY}_{VERB_PAST_PARTICIPLE} for application/domain events, rendered UPPERCASE in Substrate (e.g. BIRD_HOPPED, PAYMENT_DECLINED, FILE_COUNTED in the worked 0.1.json). Note the deliberate divergence from DDD's PascalCase: Substrate uses UPPERCASE_SNAKE for application/domain tags (greppable, stable identifiers — foundation 01's design principle that tags are 'stable identifiers, not prose'), while the 13 kernel kinds RETAIN their spec PascalCase under the reserved substrate. namespace. Two name-shapes by design: substrate.PascalCase for kernel/control-plane, UPPER_SNAKE past-participle for domain. Irregular past participles handled explicitly (BIRD_FLIT).

- **Claim.** Signal tags must be treated as a stable public API / contract, validated at the point of emission, not negotiated at ingest — and a strict (extras-rejected) posture is the default for payload validation.
  - *Evidence:* foundations/01 (kit original): tags are 'an API'; 'RECORD_ARM_REJECTED is better than a prose sentence... greppable, recognizable, survives refactoring.' PRINCIPLES commitment 2: 'Schema enforced at the speaker's mouth... Out-of-vocabulary tags raise. Malformed payloads raise.' BOOTSTRAP Step 3 Architect action: 'Decide the validator-extras posture (default: strict; opt-in to documentation-only-extras only if appropriate).'
  - *Genre:* kit original spec (primary source for this task)
  - *Bearing on the grammar:* Confirms the strict validator-extras posture mandated in the task (payload extras rejected by default). The 0.1.json worked example demonstrates minimal-but-complete payloads (FILE_COUNTED: bytes/lines/words/chars) — exactly enough to reconstruct the decision, no more. Strata (event | ambient | summary | incident) are the four base categories in VOCABULARY.json; project-specific architectural-boundary categories are layered on top. Every ambient tag MUST carry a cadence invariant (Layer 4 cross-check); incident-stratum tags MUST carry diagnostic-required Evidence (Layer 7). These are mechanical halts in BOOTSTRAP, not suggestions.

**Recommendations:**
- Keep the dependency-ordered walk (Layer 0->7) but explicitly reject the pure layer-cake's sealed hand-off model: Cimiano himself published that the strict split is 'not viable.' Substrate's viability rests on the back-propagation loop (PRINCIPLES line 47) plus Architect ratification at every layer boundary. Make this explicit in the rationale doc so a future session does not mistake the stack for an automatic pipeline.
- Plan for upper-layer sparseness as a feature, not a bug. Layers 5/6/7 in 0.1.json should be expected to underspecify; surface every gap as a typed proposal (SEQUENCE_RULE_PROPOSED, INVARIANT_PROPOSED) with a spec citation rather than agent-authored axioms — axioms are hard even for humans (peer-reviewed finding).
- Enforce source-citation-per-proposal as the anti-hallucination grounding check. The KG literature shows ungrounded invention is THE failure mode; a proposal with no 'which document, which sentence' citation should be inadmissible. This operationalizes commitment 3.
- Transcribe the 13 kernel/control-plane kinds verbatim in spec PascalCase under the reserved 'substrate.' namespace (e.g. substrate.ProducerEmittedInvalidEvent). Any paraphrase (InvalidEmission) is a hallucinated relation and must be rejected in review. Maintain the two-name-shape rule: substrate.PascalCase for kernel, UPPER_SNAKE past-participle for application/domain tags.
- Bind categories to bounded contexts (architectural boundaries), never to class/file names. Use TAG_SPLIT_PROPOSED when one surface tag spans two contexts (DDD polysemy) and ENTITY_MERGE_PROPOSED when one entity wears different surface forms across docs. Both route to the Architect; neither is resolved silently.
- Keep the strict validator-extras posture (payload extras rejected) as default and document any documentation-only-extras opt-in in the rationale doc per BOOTSTRAP Step 3. Cross-check the mechanical halts: every ambient tag needs a Layer-4 cadence invariant; every incident tag needs Layer-7 diagnostic Evidence.
- Distinguish the genre of every cited best practice in the rationale doc. Past-tense event naming has convergent support across official vendor docs (Microsoft) AND practitioner consensus — high confidence. The layer-cake critique is peer-reviewed — high confidence. The LLM-KG mitigation patterns are largely arXiv preprints — treat as directionally sound but not settled; do not cite a preprint as established fact in the locked vocabulary.

## Strand: SUBSTRATE'S CITED PRIOR ART — vocabulary/naming lessons for the bus + append-cycle + lifecycle kinds

- **Claim.** Linda's primitive names are verbs of effect on the shared space (out, in, rd, eval), not nouns for participants — and eval is the one that creates a *process*, which becomes passive tuple data once it finishes. Tuple existence is independent of the producer's lifetime ('generative communication').
  - *Evidence:* Gelernter 1985 (ACM TOPLAS 7(1):80-112): out(t) inserts a tuple and the process 'continues immediately'; in(N,...) withdraws a matching tuple and 'suspends until one is available'; read/rd is identical to in but 'the matched tuple is not withdrawn'; eval 'starts a concurrent process which evaluates to a tuple which is then added to TS' (a live/active tuple becoming passive data). Matching is associative by template with actual values vs typed formals/wildcards. 'The tuple generated by A has an independent existence in TS' beyond A's lifetime.
  - *Genre:* peer-reviewed paper (+ practitioner summary: the morning paper)
  - *Bearing on the grammar:* Validates Substrate's anti-anthropomorphic discipline at the root: name the act, not the actor. Substrate already does the eval lesson cleanly — TriggerFired (PascalCase kernel kind) records the act of process creation as an event on the log, and the resulting Producer's emissions are plain post-validation tuples whose 'independent existence' is exactly 'being on the log after validation' (v15 change #1). Confirms application tags should be {ENTITY}_{VERB_PAST_PARTICIPLE} (the effect already happened, like a settled tuple), reserving the live/imperative sense (an act about to happen) to the substrate. control-plane kind TriggerFired. No new tag needed; this is corroboration of existing names.

- **Claim.** Flink CEP's vocabulary cleanly separates (a) the cheap declarative match grammar from (b) the action/judgment function — exactly Substrate's 'matching cheap, judgment elsewhere.' Its match grammar also gives a ready-made, battle-tested vocabulary for keyed/windowed firing.
  - *Evidence:* Flink CEP docs (stable): match side = begin/next/followedBy/followedByAny/notNext/notFollowedBy (contiguity), oneOrMore/times/timesOrMore/greedy/optional (quantifiers), where/or/until/subtype (conditions, split into SimpleCondition vs stateful IterativeCondition), within(Duration) (window), AfterMatchSkipStrategy (noSkip/skipToNext/skipPastLastEvent/skipToFirst/skipToLast). Action side = PatternProcessFunction.processMatch() / PatternSelectFunction. The two sides are different APIs.
  - *Genre:* official docs
  - *Bearing on the grammar:* Direct mapping to the Predicate taxonomy in v15 §5 (event-local | buffer-local | bus-view | composite | externalised) and the firing policies in §6 (Once | PerEvent | PerKey | WhileTrue+cooldown). CEP's SimpleCondition vs IterativeCondition is the same cut as Substrate's event-local vs View-reading predicates; CEP's within() maps to wall-clock cooldown (the demoting, replay-ceiling-dropping kind). CEP's AfterMatchSkipStrategy is the prior-art reference for what PerEvent/Once/PerKey de-duplication must specify — Substrate's spec underspecifies the skip semantics of PerEvent (does a consumed event re-arm?). Recorded as SEQUENCE_RULE_PROPOSED below. CEP keeps match-grammar terms imperative/present (the pattern is a live matcher) while Substrate's *result* of a match is the past-tense TriggerFired — consistent split.

- **Claim.** KPN names the communication discipline (blocking read on a FIFO channel) and earns determinacy from it; Substrate deliberately rejects both the point-to-point channel vocabulary and the determinacy guarantee.
  - *Evidence:* Kahn 1974: deterministic sequential processes communicate over unbounded FIFO channels; 'reading from a channel is blocking while writing is non-blocking'; behaviour 'does not depend on the timing of computation nor on communication delays.' v15 §Why one bus: 'Point-to-point channels (KPN-style): every Producer pair ... needs its own channel. N² wiring.'
  - *Genre:* peer-reviewed paper (+ Wikipedia/textbook corroboration)
  - *Bearing on the grammar:* Confirms Substrate must NOT introduce any channel / port / pipe noun into the vocabulary — there is exactly one Bus and one total order. The blocking-read backpressure of KPN is replaced by admission-queue backpressure (await submit()), so the grammar's backpressure vocabulary attaches to the admission queue, not to per-edge channels. Reinforces that no per-edge or per-subscription tag belongs in the signal grammar. No new tag; a boundary constraint on the ontology (Layer 0 entities must not include 'Channel').

- **Claim.** Naiad/Timely contributes the precise vocabulary for *progress* — pointstamp, epoch, loop counter, frontier, and the OnRecv/OnNotify/SendBy/NotifyAt callbacks — i.e. 'we know no more messages will arrive at/below this timestamp.' Substrate has no first-class word for this; it expresses it only as an ad-hoc predicate.
  - *Evidence:* Murray et al. SOSP 2013: a pointstamp is (location, timestamp); timestamp = (epoch, loop_counter); the frontier is 'the set of timestamps beyond which no more messages will arrive'; OnNotify fires when a timestamp is complete. v15 §prior work: 'Naiad's frontier ... lets iterations know when an iteration is complete. Substrate's Triggers do similar work with event predicates.' v15 §Topology patterns expresses 'wait for all running Producers of kind K' as the predicate 'count(ProducerCompleted for K) == count(ProducerStarted for K).'
  - *Genre:* peer-reviewed paper
  - *Bearing on the grammar:* Substrate re-derives the frontier as a *counting predicate over lifecycle events* rather than naming it. This is a genuine gap the spec leaves to the topology author (v15 §Costs: 'topology author has to reason about predicate satisfaction conditions'). Recorded as INVARIANT_PROPOSED (a 'cohort complete' temporal invariant: for any Producer kind K and triggering cohort, count(substrate.ProducerCompleted)+count(substrate.ProducerFailed)+count(substrate.ProducerCancelled) for K eventually equals count(substrate.ProducerStarted) for K) — this names the frontier condition in the grammar's Layer-4 temporal_invariants without adding a primitive. Do NOT mint a 'FrontierReached' tag: the spec is explicit that progress is a derived predicate, not an emitted event; minting one would fabricate a kernel kind.

- **Claim.** SEDA names the unit of decomposition 'stage' and the coupling 'queue' with per-stage admission control and a 'controller' that adapts the thread pool. Substrate keeps the bounded-queue/admission-control idea but collapses many queues into one bus.
  - *Evidence:* Welsh et al. SOSP 2001: application = 'a network of event-driven stages connected by explicit queues'; 'performing admission control on each event queue' keeps the service 'well-conditioned to load'; a 'controller' adjusts the thread pool 'based on an observation of the event queue.' v15 §Why one bus: 'Per-stage queues (SEDA-style): each stage has its own input and output queues. Works for static pipelines, doesn't support dynamic spawn.'
  - *Genre:* peer-reviewed paper (+ Wikipedia corroboration)
  - *Bearing on the grammar:* Endorses Substrate's single bounded admission queue as the one backpressure point and warns against per-stage-queue vocabulary (no 'stage', no per-stage 'inbox'/'outbox' nouns). SEDA's 'controller observing the queue' maps onto Substrate's recorded enforcement decisions — the analogue of SEDA's silent adaptive controller is Substrate's *explicit* PredicateQuarantined event (v15 §5: 'Silent enforcement is not an option'). Lesson: where SEDA mutated silently, Substrate must emit. Confirms the existing kernel kind; suggests any future admission-control backpressure decision (e.g. a producer blocked on submit long enough to matter) should also be a typed event rather than silent — recorded as NEW_TAG_PROPOSED (substrate-namespaced) below, flagged as a proposal because the spec does not currently emit one.

- **Claim.** Temporal supplies the durable-replay vocabulary (Event History, replay, determinism constraint) and the crucial push-vs-stage contrast: Temporal *Signals* push asynchronously into a *running* workflow; Substrate explicitly cannot, because Producer input is immutable, so Routes stage for *future* instantiations.
  - *Evidence:* Temporal docs: Event History is 'an append-only, complete, ordered log of everything that has already happened in a Workflow'; replay 'replays the Event History step by step'; a Signal is 'an asynchronous message sent to a running Workflow Execution that can change its state', recorded in Event History; Query is read-only, Update is write-with-response. v15 §prior work: 'Temporal's signals are pushed into running workflows; Substrate Routes stage messages for future Producer instantiations because running Producers have immutable input.'
  - *Genre:* official docs
  - *Bearing on the grammar:* Sharpens why Substrate names the mechanism Route/InjectionApplied (a staging act at an instantiation boundary) and NOT 'Signal' — borrowing Temporal's 'Signal' would falsely imply mid-life mutation, which v15 §1 (Decision #6 Input immutability) forbids. The InjectionApplied kernel kind is the correct, faithful name; do not paraphrase to 'SignalDelivered'. Temporal's Event-History-as-replay-source is exactly Substrate's bus-is-the-run-record (v15 §Replay); the past-tense '...has already happened' framing corroborates the {ENTITY}_{VERB_PAST_PARTICIPLE} tense rule for application tags — the log records settled facts. Temporal's determinism caveat backs Substrate's honest Level-3(a)/(b) split and the wall-clock-cooldown demotion flag.

- **Claim.** Reactive Streams supplies the credit-based backpressure vocabulary (request(n) demand, onNext/onError/onComplete signals) on point-to-point flows; Substrate attaches the credit-pool analogy to the single admission queue, not to per-subscription consumers, and so does NOT inherit the 'slow consumer' term.
  - *Evidence:* Reactive Streams JVM spec: four interfaces Publisher/Subscriber/Subscription/Processor; signals onSubscribe/onNext/onError/onComplete and Subscription.request(long n)/cancel(); rule: 'The total number of onNext's signalled ... MUST be less than or equal to the total number of elements requested.' v15 §prior work: 'the credit-pool analogy attaches to the admission queue ... The per-subscription slow-consumer concept doesn't apply because there are no per-subscription consumers in Substrate.'
  - *Genre:* standard/spec (de-facto standard, the reference RS implementation)
  - *Bearing on the grammar:* Confirms backpressure vocabulary lives at the admission queue (the 'credit pool' = the queue bound, sized per Reactive Streams) and that the grammar must NOT introduce Subscriber/Subscription/demand tags. Note a terminology collision to guard: Substrate's View 'subscribes to a set of event kinds' (v15 §Views) uses 'subscribe' in a non-RS sense (a read projection, not a credit-bearing consumer) — recorded as a NOTE/INVARIANT_PROPOSED to keep the grammar glossary explicit that View-subscription ≠ RS Subscription, so neither implies backpressure semantics. RS's onError/onComplete terminal-signal pair corroborates Substrate's terminal lifecycle trio ProducerCompleted/ProducerFailed/ProducerCancelled.

**Recommendations:**
- Keep the 13 kernel kinds verbatim in PascalCase under the substrate. namespace exactly as in the v15 lifecycle table (lines 476-489): substrate.RunStarted, substrate.TriggerFired, substrate.InputBuildFailed, substrate.ProducerStarted, substrate.ProducerEmittedInvalidEvent, substrate.ProducerCompleted, substrate.ProducerFailed, substrate.ProducerCancelled, substrate.InjectionApplied, substrate.PredicateQuarantined, substrate.TerminationMatched, substrate.RunFinalised. Never paraphrase (no InvalidEmission, no SignalDelivered, no FrontierReached). The cross-checks against Linda/Temporal/RS all confirm these names already carry the right meaning.
- Application/domain tags emitted by Producers stay UPPERCASE {ENTITY}_{VERB_PAST_PARTICIPLE}. Linda's settled-tuple semantics and Temporal's 'everything that has already happened' both reinforce the past-tense rule: the bus records facts that have landed, not commands. Example domain tags the worked topologies imply (all PROPOSED, pending the Vocabulary Session, with spec citation): CANDIDATE_EMITTED, SCORE_ASSIGNED, CHALLENGE_RAISED, SUBTASK_PROPOSED, PAYOFF_COMPUTED, RETRY_EXHAUSTED (v15 lines 524, 654-680, 695-699).
- INVARIANT_PROPOSED (cohort frontier): add a Layer-4 temporal invariant naming Naiad's frontier in Substrate terms — for a Producer kind K, count(substrate.ProducerCompleted)+count(substrate.ProducerFailed)+count(substrate.ProducerCancelled) for K eventually reaches count(substrate.ProducerStarted) for K (the 'all running Producers of kind K done' condition). Source: v15 §Topology patterns / Progress gating, lines 541-547. Do NOT emit a new event for this — the spec is explicit progress is a derived predicate.
- SEQUENCE_RULE_PROPOSED (PerEvent/Once/PerKey re-arm semantics): the spec underspecifies whether a consumed matching event re-arms a Trigger and how PerKey keys expire — Flink CEP's AfterMatchSkipStrategy (noSkip/skipToNext/skipPastLastEvent/skipToFirst/skipToLast) is the prior-art reference to resolve this. Source: v15 §6 firing policies (lines 386-398) + Flink CEP docs. Flagged as proposal, not asserted, because v15 does not state the skip rule.
- Categories must follow architectural boundaries, not class names (per VOCABULARY.json discipline and v15 §Vocabulary discipline). The clean boundary in Substrate is control-plane (substrate.* lifecycle, the 13 kinds) vs application payload (user kinds). Map these to strata: lifecycle terminal/decision kinds (ProducerFailed, ProducerEmittedInvalidEvent, PredicateQuarantined, InputBuildFailed) sit in the incident stratum; ProducerStarted/Completed/TriggerFired/InjectionApplied are event stratum; RunStarted/RunFinalised are summary stratum (boundary roll-ups carrying the topology manifest / final output). No ambient-stratum kernel kind exists — ambient is reserved for application sensor/metric Producers (v15 §Multi-modal: runtime metric collectors), recorded as a note so the Vocabulary Session does not leave 'ambient' falsely empty or wrongly populated.
- Guard two terminology collisions in the grammar glossary: (1) View 'subscribes to event kinds' (v15 §Views) is NOT a Reactive Streams Subscription — it carries no credit/demand; (2) do not import KPN 'channel', SEDA 'stage', or Temporal 'Signal' as entity names — each implies a structure (point-to-point edge, per-stage queue, mid-life push) that Substrate's single-bus + immutable-input model explicitly rejects (v15 §Why one bus, Decision #6). Record these as Layer-0 ontology exclusions.
- NEW_TAG_PROPOSED (substrate-namespaced, flagged because the spec does not currently emit it): consider whether prolonged admission-queue backpressure deserves a typed event analogous to SEDA's controller observation, so that 'a Producer was throttled at submit' is on the log rather than invisible. v15 currently makes backpressure a silent await submit() (lines 99-105). This conflicts mildly with the §5 'silent enforcement is not an option' philosophy applied to quarantine; raise as an open question for the spec authors rather than minting the kind unilaterally.

## Strand: EVENT-LOG & OBSERVABILITY SCHEMA STANDARDS — envelope, payload, stratification, and canonical-encoding recommendations for Substrate, grounded in CloudEvents 1.0, OpenTelemetry semantic-convention naming, Elastic Common Schema, RFC 8785 (JCS), and Git/CAS content-addressing practice.
