## Intent and scope

This vocabulary is the typed signal grammar for **Substrate**, a concurrent streaming dataflow runtime. Unlike a typical SDD project, the runtime’s subject matter *is* a typed event log — so Layers 0–2 are largely a **faithful transcription** of the kernel spec (v15) and technical spec (DRAFT 5), not an inference from prose. The 12 `substrate.*` lifecycle kinds are the control-plane vocabulary every run emits; application Producers declare their own kinds per-topology (NOT part of this locked vocabulary — v0.1 deliberately mints zero application-namespace tags; see proposals). The grammar’s job here is to (a) transcribe the lifecycle kinds and their spec-grounded payloads exactly, (b) name the runtime ontology (Layer 0), (c) make the append-cycle ordering and replay/record evidence explicit (Layers 4–7), and (d) surface — as typed proposals, never silent fills — the places where the specs are underspecified relative to their own conformance checks.

## The one finding that gates the lock

The adversarial verification surfaced a coherent, load-bearing gap: **the runtime-emitted lifecycle events carry `producer: null` (envelope, tech §3.4) and spec-empty payloads, so the SUBJECT Producer of `ProducerStarted/Completed/Cancelled/Failed` — and the route/slot/message of `InjectionApplied` — are not on the frame.** Yet conformance check 1 (retry enrichment scoped to the failed unit of work), check 11 (provenance closure), and reference topology R-1 (cohort-frontier counting + cancel-all-others) all need them. `F-PROD-4` types `ProducerId` but never states it rides the lifecycle payload. This is a genuine **spec gap**, not an authoring choice: it is filed as `P-SUBJECT-ID` (and `P-INJECTION-FIELDS`) and **recommended for ratification into v0.1**, and it likely warrants a kernel **v16** reconciliation note. Until ratified, the affected dual-contract pairings are honestly marked CONDITIONAL (below). Provenance closure itself is independently satisfiable via `TriggerFired` + the non-null `producer` field on a Producer’s own subsequent application events.

Two smaller fidelity fixes were applied during synthesis cleanup: a fabricated session attribute `vocab_version` (present in NO spec) was removed; and a `ProducerEmittedInvalidEvent` ‘envelope producer is non-null’ claim that was asserted as fact (spec-contested) was demoted to `P-INVALID-PRODUCER-FIELD`. The kernel-vs-tech drift on `TriggerFired.factory` is filed as `P-TRIGGERFIRED-FACTORY`.

### Layer 3 — Session

The session is the **Run**: opens at `substrate.RunStarted` (seq 0, frame 0, exactly once), closes at `substrate.RunFinalised` (at-most-once, terminal; legitimately absent after a torn tail per tech §5.2). Persistent attributes carried once in `RunStarted` (not repeated per tag): run_id, topology (manifest: producer_kinds + schema descriptors + fingerprints, triggers, routes, views, policies), baseline (fixtures, seed, env), config (fsync policy, admission bound, budget_us, hysteresis_k), replay_ceiling (3a|3b, in the manifest; demoted by any wall-clock cooldown). The fabricated `vocab_version` attribute was removed.

### Layer 4 — Temporal invariants (6)

- **pairing** — APPEND-CYCLE ORDERING (the canonical six-step total order inside the single writer, per spec): for each admitted/control event e — (1) Validate; (2) Sequence+append (assign seq N, frame, append); (3) Update Views synchronously (state is now as-of-N); (4) Stage Routes (matching Routes compute transform(e) and stage to their Slot) — BEFORE Predicates; (5) Evaluate Predicates in registration order against the as-of-N snapshot and fire Triggers (input_builder runs; substrate.TriggerFired or substrate.InputBuildFailed enqueued on the control queue; Producer scheduled post-cycle); (6) Drain the control queue FIFO, each queued event running its own full append cycle (seq N+1, N+2, ...) before any further admitted payload event. NOTE: the spec order is Views(3) THEN Routes(4) THEN Predicates(5); a Trigger fired by event N CAN read messages a Route staged from event N (no one-event delay — the Retry pattern relies on it). Reentrant appends from inside steps 3-5 raise ReentrantAppendError.
- **window** — AS-OF-N SNAPSHOT: a Predicate or input_builder evaluated at seq N sees Views reflecting exactly all events with seq <= N and Route messages staged as of step 4; every Predicate in step 5 of one cycle sees the SAME snapshot. Views are the single writer's exclusive state (no concurrent update).
- **cooldown** — COOLDOWN logical-by-default: a Trigger cooldown is counted in append cycles matching the predicate's subscription (logical, replayable at every level the run otherwise supports). Wall-clock cooldown is opt-in and DEMOTING: registering ANY wall-clock cooldown on ANY Trigger flips the run's replay_ceiling from 3a to 3b at RunStarted time and records the cooldown flag in the manifest; logical cooldowns leave the ceiling at 3a.
- **eventually_must** — COHORT FRONTIER (Naiad frontier re-derived as a counting predicate, NOT an emitted event): for any Producer kind K and triggering cohort, count(substrate.ProducerCompleted)+count(substrate.ProducerFailed)+count(substrate.ProducerCancelled) for K eventually equals count(substrate.ProducerStarted) for K — the 'all running Producers of kind K done' condition. Do NOT mint a 'FrontierReached' kind: progress is a derived predicate, not an event.
- **cadence** — AMBIENT CADENCE (the only ambient surfaces; both OFF-bus): writer_stats.jsonl is sampled at WRITER_STATS_INTERVAL_MS (default 1000ms; EWMA over a 1s window for cycles_per_sec); the diagnostic sidecar diagnostics.jsonl is flushed at SIDECAR_FLUSH_MS (default 500ms) or at fsync boundaries. Satisfies the BOOTSTRAP Step-5 halt (every ambient stratum entry needs a cadence invariant). NO on-bus kernel kind is ambient.
- **forbidden_after** — DIAGNOSTIC INVARIANCE (the boundary rule separating event from ambient/incident): enabling the diagnostic sidecar OR writer_stats MUST leave the bus log bit-identical; sidecar records are keyed by observed seq but NEVER sequence-numbered; the writer's append cycle does NO sidecar/filesystem I/O on the hot path. Therefore no event-stratum bus tag may be minted for seal/blob/replay/inspect/diagnostic acts.

### Layer 5 — State-transition rules (5)

- **pairing_ordering** — RUN-BOUNDARY: substrate.RunStarted is seq 0 (frame 0, exactly once, run-open); no substrate.* or application event may precede it. substrate.RunFinalised is terminal (at most once, run-close, last-if-present); no event follows it. CARVE-OUT: on the §5.2 fsync-failure path RunFinalised is legitimately ABSENT (torn tail) — recovery reports 'incomplete run — no RunFinalised — torn at seq N'; absence-after-torn-tail is valid, not a missing-terminal defect.
- **pairing_ordering** — PRODUCER LIFECYCLE: for a given Producer instance, substrate.ProducerStarted precedes exactly one terminal in {substrate.ProducerCompleted, substrate.ProducerFailed, substrate.ProducerCancelled}; substrate.ProducerEmittedInvalidEvent for that instance may occur zero-or-more times strictly between Started and its terminal. The re-arm/AfterMatchSkip question for the firing Triggers is left open (SEQUENCE_RULE_PROPOSED).
- **forbidden_after** — PAUSE/RESUME RE-ENTRY: a substrate.TerminationMatched{decision:'pause-await-input'} is a NON-terminal boundary — it pauses the Run WITHOUT a RunFinalised and MUST carry a resume_condition; the Run is re-entered when a Trigger fires on the event named by resume_condition. Distinguished from finalise-run (which leads to RunFinalised). CLI exit codes distinguish paused from finalised.
- **forbidden_after** — SEALING PAIRING (off-bus writer FSM, Layer-5): for any segment the hot ('.open.' infix, append-only) state precedes the sealed (events-N.jsonl, immutable) state; seal order is fsync(hot) -> rename -> fsync(dir) -> create next .open -> fsync(dir) -> manifest update; a sealed segment MUST NEVER be reopened for writing, including by recovery; recovery operates ONLY on the single .open segment (first unterminated/unparseable/crc-mismatched line is the cut point: ftruncate + fsync). Write-ahead-blob: a blob is written and fsynced BEFORE the referencing frame is appended.
- **terminal** — VIEW-FAILURE TERMINAL: a View raising in update() is fatal for the run; the writer appends substrate.RunFinalised{reason:'view_failure', view, seq, error} and terminates. This is the incident-stratum instance of the RunFinalised summary tag.

## Research grounding

The grammar was grounded by a parallel research pass before drafting (full findings + citations in `research-pass.md`). Load-bearing conclusions: (1) the ontology-learning **layer cake** justifies expecting Layers 5–7 to be sparser than 0–2 and routing upper-layer gaps to the Architect rather than self-authoring — and its *originator’s* critique (‘the layer cake is not viable’ as a sealed automatic hand-off) validates SDD’s loop-back discipline (propose, don’t infer); (2) the KG-construction literature’s dominant failure mode — **ungrounded invention / hallucinated relations** — is exactly why every proposal carries a source citation and the 12 kernel kinds are transcribed verbatim; (3) **DDD bounded contexts** ground the category-as-architectural-boundary rule and the TAG_SPLIT/ENTITY_MERGE proposal types; (4) **past-tense event naming** (Microsoft DDD/CQRS, eventsourcing.dev) is the convention for application tags, with the deliberate UPPER_SNAKE divergence for greppability; (5) **CloudEvents / OTel / RFC 8785** ground the envelope discipline and the canonical-encoding evidence constraints (number-precision pitfalls).
