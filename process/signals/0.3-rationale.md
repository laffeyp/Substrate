# Substrate locked vocabulary v0.3 — rationale

Locked 2026-08-27. Successor to v0.2 (2026-06-13). v0.2 stays on disk under `signals/0.2.json` as the audit trail per sdd-kit-2 hard rule 12; nothing there is deleted.

## What v0.3 changes

Two additive optional fields on the `substrate.ProducerCancelled` payload:

- **`cause`** — a short enum-like string naming why the producer was cancelled. `"external"` when `Runtime.cancel_producer(instance, cause=...)` fired the cancel from outside the run's own policy machinery. `"policy"` when a `TerminationPolicy` path (today: `_cancel_others`) decided the cancel. Absent on cascade cancels during run teardown (the task-cleanup path with no adjudicating policy).
- **`caller`** — an optional free-form identifier of the caller that dispatched the cancel. Populated with the policy's name for `cause="policy"` (e.g. `"cancel_all_others"`). Populated with a caller-supplied string for `cause="external"` (e.g. `"daemon:interrupt"`, `"cli:ctrl-c"`). Absent when the caller did not name itself.

Both fields are OPTIONAL. Existing consumers that key on `producer` are unaffected. `validator_extras` stays STRICT.

Kernel v15's twelve reserved lifecycle kinds are unchanged. `substrate.ProducerCancelled` was already one of the twelve; the change lives inside its payload.

## Why the change

Sprint 217c red-team pass on `08dcaed6`. The commit shipped `Runtime.cancel_producers(kind)` — a new kernel primitive that cancels producer tasks from outside the run. The primitive wrote no provenance envelope. A reader running `explain_producer` on a cancelled instance saw: started, cancelled, no adjudication. The record was honest about the effect and silent about the cause.

Every other kernel cancel path has provenance. A policy-driven cancel writes `substrate.TerminationMatched(decision="cancel_others")` before the tasks die — the reader can trace back from ProducerCancelled to the policy that decided. A budget-driven cancel writes `substrate.ProducerFailed` with an `error="budget_exceeded"` payload. Bare external cancels broke that pattern.

Two shapes were considered:

- **A new reserved kind** — `substrate.CancelDispatched` written before the cancel, then the standard `ProducerCancelled` on the CancelledError handler. Two envelopes per cancel. Kernel v15's twelve-kind boundary would grow to thirteen.
- **Payload extension on `ProducerCancelled`** — additive optional fields naming the cause and caller. One envelope per cancel. Kernel v15's twelve-kind boundary stays.

The payload extension carries the causality one hop away from the reader who wants it (`ProducerCancelled.payload.cause`) rather than requiring a two-envelope join. Kernel v15 stays intact. The change is additive: pre-v0.3 consumers keep working.

## What v0.3 does NOT change

- No new reserved kinds. Kernel v15's `LIFECYCLE_KINDS` tuple stays at twelve entries.
- No changes to any other envelope's payload.
- No changes to `Runtime.run`, `Runtime.resume`, `_bootstrap`, or `_resume_bootstrap`.
- No changes to the append cycle, admission bound, or writer loop.
- No changes to any Producer, Trigger, Route, or View primitive.

## Migration posture

Records written under v0.2 remain valid under v0.3 readers. `producer` is still the only required field on `ProducerCancelled`. A v0.3 reader parsing a v0.2 record sees `cause` and `caller` absent; the reader defaults to "unknown provenance" or omits the annotation from its projection.

Records written under v0.3 by earlier code paths (task cleanup on run teardown, cascade cancels) may also have `cause` and `caller` absent. That is legitimate: those cancels have no adjudicating source to name.

Every existing test that reads `ProducerCancelled.payload["producer"]` keeps working. Tests that want the new provenance read `payload.get("cause")` and `payload.get("caller")`.

## Provenance-write sites (v0.3)

- `Runtime.cancel_producer(instance, cause="external", caller=None)` — writes `{"cause": cause, "caller": caller}` into `RunState.cancel_reasons[instance]` before dispatching `task.cancel()`. Default cause `"external"`.
- `Runtime._cancel_others(event)` — writes `{"cause": "policy", "caller": self._termination.name}` into `RunState.cancel_reasons[inst]` for each victim before dispatching `task.cancel()`.
- `_producer_task`'s `except asyncio.CancelledError` handler reads `RunState.cancel_reasons.get(instance)` and threads the fields into the `ProducerCancelled` payload it enqueues.
